# Documentation reconciliation review checklist

> This PR is documentation-only. **Do not merge as an implementation
> claim.** Target semantics, deployed behaviour and historical
> diagnostics are deliberately distinguished.

## Commit boundaries

1. **Constitutional clarity:** ten invariant headings remain exactly
   ten, causal relatedness / selected measurement lineage / governing
   Cycle clock stay distinct, no extra measurement or movement edge.
2. **Tragedy lifecycle:** direct zero-Charge Write encounter, one
   Tragedy/Receipt, Resolution freezes Variant/Revise, terminal
   continuation, same-lock recursive exhaustion, Rest-only in exhausted
   Regions, unchanged recovery provenance.
3. **Observable target:** Phase Profile C1, null initial interval,
   preceding-Phase reference for same-Phase Revision, seven fixed
   comparison slots, Historical Extent/Rhythm, prospective Closure,
   Commit preservation. Existing attenuation A remains baseline;
   alternative B remains unresolved.
4. **Historical reconciliation:** old documents and migrations remain
   accessible with explicit status; no old snapshots or evidence
   reinterpreted; links to proposed target are reviewable.

## Required semantic regression scenarios for a future implementation

- A passive Cycle changes an expressive node to Charge zero:
  **no Tragedy**. A later lawful direct Write encounter at zero:
  **Tragedy**. Rest does not trigger either.
- A single-lineage Region enters Resolution and Exhaustion atomically
  on first Tragedy. Existing participants in it have **Rest only**.
- Two zero encounters with a live third sibling do **not** exhaust the
  Region. The unique regional Tragedy/Receipt remains unique.
- Resolution rejects Variant (Phases 1/2/4) and Revise (2/3/4),
  but leaves ordinary non-terminal Reclassify, Reconcile, Instrument,
  Attestation, Traverse and Commit governed by their existing gates.
- A successful Commit continues through a descendant basin; later
  descendant exhaustion closes that route but not a viable sibling.
- Exhaustion propagates backward through genuine causal relationships,
  respecting recorded arrival paths and multi-parent provenance.
- An unrelated Region in the same Horizon remains unaffected.
- C1 first expressive birth has a coordinate but `null` interval.
  Same-Phase Revision compares to selected preceding-Phase stamp.
  No null interval enters the Phase-local mean denominator.
- The seven-slot cross-Domain comparison retains neutral zero
  contributions for unavailable comparisons, not fabricated
  empirical zeros.
- Reconcile with different Phase-4 birth coordinates uses the acting local
  Gate for its Phase-5 interval, retains both genuine edges and excludes the
  secondary operand from temporal reference selection. Reverse the acting Gate
  and verify the corresponding selected interval.
- Foreign-source Bias records its creating basin's coordinate and an unavailable
  interval when no eligible local causal predecessor exists. No synthetic local
  Gate edge, foreign-clock subtraction, Receipt observation or zero is allowed.
  Foreign Cycle entries cannot advance the local clock; subsequent lawful local
  development can use the imported Proposition's valid birth coordinate.
- Cycle entry updates prospective Closure on all expressives governed
  by the entry Committal, not merely heads; Attestation updates
  targeted Chirality; Correspondence remains birth-resolved.
- Commit preserves selected resolved expressive measurements and
  component directions. No generic hard-Supersession preservation.
- Attenuation A and B remain separate diagnostic controls; do not
  choose B because it produces more favourable Charge or Domain sign.
- Existing historical snapshots, Receipts, Tragedy and Exhaustion
  witnesses remain immutable.

## Open review boundary

The precise implementation action-to-target mapping for qualifying
direct expressive Writes must follow the authoritative participation
schema, including Traverse, Instrument and Attestation. This is a
documentation review of the agreed semantic category, not a
permission to broaden actionability. Future code changes need their
own review and tests.

No production code, migrations, tests or runtime schemas are
modified by this PR.
