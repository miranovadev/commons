# Direct encounter and recursive proof architecture

Authority: [approved lifecycle](tragedy-resolution-target.md).

| Component | Responsibility |
| --- | --- |
| ContributionDispatcher | Lock, ordinary authorisation, event resolution, direct target observation |
| TragedyService | Immutable terminal encounter, first regional Tragedy and unique Receipt |
| PhaseGenerationService | Shared Resolution and terminal restrictions for plans and dispatch |
| TerminalContinuationService | Actual local causal routes and genuine committed descendant status |
| ExhaustedContinuationService | Request-local derived terminal-path view, not a second authority |
| ExhaustionService | Locked remaining-continuation evaluation, unique proof and parent recursion |
| RegionalExhaustionMembership | Rebuildable creating-Cycle ownership projection |
| ExhaustionAuditService | Read-only event/proof consistency diagnostics |
| HorizonReceiptService | Unchanged narrowly scoped one-use warrant and ordinary Receipt protections |
| RecoveryBasinResolver | Unchanged recorded backward-lineage recovery and crossing authority |

Rest and exploration-epoch failure remain separate. A versioned failed attempt
is not persistent terminal authority and cannot substitute for an Exhaustion
proof. Measurement updates are not encounter publishers. The separate Rest
crossover bound is unchanged.

The Stage 4 migration chain targets a fresh database. There is no new historical
upgrade path or compatibility authority. See the [implementation register](tragedy-resolution-implementation.md)
for verification status and limits.
