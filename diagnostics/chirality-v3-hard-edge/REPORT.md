Ancestral Committals stop further expansion. `calculate()` calls raw local calculators, applies `1/(1+d)^2`, includes neutral-node denominator mass, and normalizes Correspondence and Chirality. ## Existing invariant and integration limits

This candidate deliberately changes an existing measurement contract. `LineageAttenuationTest::test_preview_and_actual_committal_use_identical_distances` expects prospective and actual Committal heads to use matching incoming-lineage geometry. `test_raw_calculation_never_reads_or_reuses_accumulated_projections` establishes that ordinary raw calculations ignore accumulated projections. `LocalMeasurementService` states that independence explicitly.

The candidate would need an explicit canonical-boundary exception to that raw-value contract, consistently applied to prospective and actual Commit observations. It must use a durable canonical record, not a mutable disposable projection. It preserves the separate existing invariants that Closure is head-local, ancestral Committals terminate the walk, shared ancestors are counted once, and snapshot history is immutable.

For this numeric diagnostic, there is no unresolved choice about Commit Correspondence, Chirality, Closure, Tension or Domain. One integration question remains outside the tested record: production component/direction APIs currently expect local Orientation/Cadence metadata. The candidate has only a canonical aggregate at this boundary. We deliberately do not fill those fields with fabricated local values or silently choose a new direction-inheritance rule. The diagnostic provider rejects requests to manufacture C1 local Chirality components. Later lifecycle/direction behavior beyond the single child is not claimed or tested here.
